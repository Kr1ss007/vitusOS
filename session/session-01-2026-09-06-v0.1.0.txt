1. EXECUTIVE SUMMARY & REPOSITORY CONTEXT
--------------------------------------------------------------------------------
vitusOS is a macOS-grade, bare-metal, Wayland-native operating system built from
scratch in Rust, C11, GLSL, and pure UEFI C. The system is engineered around a
hardened, fault-tolerant, high-performance two-process architecture powered by
the AnimusEngine (AE) compositing and animation pipeline, Vulkan 1.3 scanout,
Smithay Wayland protocol infrastructure, Hardware Enclave Vault (HEV), and
proprietary internal communication buses (EventBus and EOBus).

This document serves as the canonical record of everything built, refactored,
hardened, and integrated from the initial zero-state commit up to the current
production state (v0.1.0).


2. CORE ARCHITECTURAL FOUNDATIONS & DIRECTIVE PIVOTS
--------------------------------------------------------------------------------
2.1 Architectural Rename: OSF -> AnimusEngine (AE)
    - Historical Context: Early architecture documents referred to the compositing
      and shell surface protocol as "OSF" (Operating System Foundation / Shell Framework).
    - Directive Pivot: All references to OSF were formally deprecated and renamed to
      AnimusEngine (AE) throughout the entire codebase.
    - Updated Interfaces:
      * Wayland Protocol: protocol/ae-shell-v1.xml (defining `ae_shell_v1` and `ae_surface_v1`)
      * Global Menu: AEMenuRegistered protocol and dispatch structs
      * Compositor Surfaces: AESurface, AEShellRole (Panel, Dock, Overlay, Window, Dialog)
      * IPC Bridge: AEBridge (`/run/vitusos/ae-ipc.sock`)
      * Boot Service: animus-early C11 KMS splash screen

2.2 The Two-Process Architecture (Specification Document Part 28)
    vitusOS explicitly separates session management from display compositing into
    two distinct Linux processes for fault-isolation, security privilege separation,
    and uninterrupted frame delivery:

    Process 1: `vitusos-session`
    ---------------------------
    - Managed by: systemd user unit `vitusos-session.service` (Wants=graphical-session-pre.target)
    - Subsystems Owned:
      * Hardware Enclave & Vault (HEV): AES-256-GCM + Argon2id encryption for user keys
      * StateManager: JSON/disk state persistence for session, window geometry, user prefs
      * EventBus (Session-Side): Core message bus dispatching system state changes
      * EOBus (EventOutsiderBus): vitusOS-owned gateway for 3rd-party and sandboxed processes
      * SeaDrop: Device discovery and zero-configuration P2P asset transfer
      * RegistryManager (Session-Side): System-wide setting & capability registry
      * CrashManager (Session-Side): Vessel DAG, FirstResponder recovery coordinator
    - Failure Tolerance: If the graphical compositor crashes, `vitusos-session` stays
      alive. User application data, background tasks, encrypted vaults, and network
      transfers remain uninterrupted while the compositor restarts.

    Process 2: `vitusos-compositor`
    ------------------------------
    - Managed by: systemd user unit `animus-compositor.service` (After=vitusos-session.service)
    - Subsystems Owned:
      * AnimusEngine: Animation and spring-physics orchestrator
      * Vulkan 1.3 Render Pipeline: Raw ash/shaderc 7-layer CompositorRenderer
      * Smithay Wayland Engine: wl_compositor, xdg_shell, ae-shell-v1 protocol globals
      * Calloop Event Loop: 144Hz frame timer, Wayland socket, udev DRM backend, libinput seat
      * WindowManager: Floating and tiling window placement, focus DAG, z-order stack
      * WorkspaceManager: Multi-workspace isolation, spatial transitions
      * ShellController: Single centralized event routing and shell state dispatch point
      * Shell Surfaces: Top Panel (Global Menu), Dock (Gaussian magnification), Cockpit View
        (Mission Control/Expose), Control Center, Notifications, Lock/Welcome/Shutdown screens
    - Performance Guarantee: Compositor executes in a dedicated event loop at 144Hz with
      zero D-Bus blocking, delegating system daemon queries to `vitusos-session`.

2.3 Internal vs External Communication Architecture
    vitusOS strictly differentiates between internal communication pipelines and
    external Linux platform daemons:

    A. EventBus (Internal Core Bus)
       - Proprietary vitusOS intra-process and intra-session messaging bus.
       - Built on lock-free crossbeam channels and parking_lot RwLocks.
       - Dispatches typed `VitusEvent` variants (Window, Workspace, Shell, Power, Media, Audio).
       - Zero external daemon dependencies, microsecond latency.

    B. EOBus - EventOutsiderBus (External App Gateway)
       - Proprietary vitusOS IPC gateway for external and third-party applications.
       - Allows outside binaries to communicate into the vitusOS shell ecosystem
         without exposing direct raw memory or unrestricted system APIs.
       - Implements token-based caller registration, namespace access control,
         rate-limiting, and sanitized event forwarding into EventBus.
       - NOT D-Bus. Completely vitusOS-native design.

    C. AEBridge (Cross-Process Session <-> Compositor Bridge)
       - Production Unix Domain Socket: `/run/vitusos/ae-ipc.sock`.
       - Length-prefixed binary wire framing:
         [4-byte Magic: 0xAEB1] [4-byte Payload Length Big-Endian] [JSON/Bincode Payload]
       - Bidirectional non-blocking streaming with background RX threads in both processes.
       - Clean, real Linux socket implementation with zero dummy stubs or cfg(unix) mock fallbacks.

    D. D-Bus (zbus System Integration)
       - Strictly used as an external adapter to query and command Linux system daemons:
         * `org.freedesktop.NetworkManager`: WiFi SSID scanning, IP configuration, connection state
         * `org.bluez`: Bluetooth adapter power, device pairing, discovery
         * `org.freedesktop.login1`: Session power state, suspend, hibernate, reboot, poweroff
         * PulseAudio / PipeWire: System audio sink volume, mute state, default routing


3. ZERO-TO-CURRENT SUBSYSTEM CODEBASE AUDIT
--------------------------------------------------------------------------------
The repository currently contains 10 workspace crates, an EFI bootloader, 9 GLSL
shaders, systemd service units, udev rules, PAM stack configuration, and ISO tooling:

3.1 `crates/animus-physics`
    - Purpose: Physics-based animation engine driving all UI motion.
    - Key Files:
      * `src/spring.rs`: 4th-Order Runge-Kutta (RK4) numerical integrator for spring dynamics.
        Configurable stiffness, damping ratio, mass, velocity, target, and settle tolerance.
      * `src/animation_engine.rs`: Animation controller orchestrating active spring channels,
        decay animations, and 144Hz tick synchronization.
      * `src/clock.rs`: High-precision monotonic frame clock.

3.2 `crates/animus-render`
    - Purpose: Hardware-accelerated Vulkan 1.3 rendering and CPU software fallback.
    - Key Files:
      * `src/gpu/vulkan.rs`: Raw Vulkan 1.3 initialization via `ash` bindings. VkInstance,
        VkPhysicalDevice, VkDevice, Swapchain, command buffers, and descriptor sets.
      * `src/pipeline.rs`: 7-layer compositing pipeline (Wallpaper -> Desktop Surfaces ->
        Windows -> Floating Panels -> Dock -> Cockpit Overlay -> System Modal / Lock).
      * `src/framebuffer.rs`: ScanoutFramebuffer CPU rasterizer supporting Kawase blur,
        squircle SDF drawing, and drop shadow blitting into scanout buffers.
      * `src/squircle.rs`: G2 continuous curvature super-ellipse SDF rasterizer.
      * `src/font_manager.rs` & `src/typography.rs`: FontBook text rasterizer utilizing
        `fontdue`, `ttf-parser`, and `rustybuzz` for Unicode shaping and subpixel rendering.
      * `src/glyph_atlas.rs`: Dynamic GPU texture atlas caching rendered glyphs.
      * `src/smithay_renderer.rs`: Smithay GL/Gles/Glow render bridge.

3.3 `crates/animus-core`
    - Purpose: System-wide foundation, cross-process IPC, crash recovery, and state management.
    - Key Files:
      * `src/ae_bridge.rs`: Unix Domain Socket IPC between `vitusos-session` and `vitusos-compositor`.
      * `src/event_bus.rs`: In-memory thread-safe publish-subscribe EventBus.
      * `src/eobus.rs`: EventOutsiderBus client registration and message sanitizer.
      * `src/state.rs`: StateManager handling disk persistence (`/home/{user}/.config/vitusos/state.json`).
      * `src/crash/`: Complete CrashManager suite:
        - `vessels.rs`: Directed Acyclic Graph (DAG) of system components and recovery ordering.
        - `first_responder.rs`: Emergency crash detection, SIGSEGV/SIGABRT handling, core dumps.
        - `handshakes.rs`: Liveness heartbeats between session and compositor.
        - `crash_site.rs`: Black-box crash log recorder with hardware register snapshots.
      * `src/dbus/`: Real `zbus` clients for NetworkManager, BlueZ, audio, and logind.
      * `src/clipboard.rs` & `src/drag.rs`: Wayland clipboard & drag-and-drop state machines.
      * `src/accessibility.rs`: Screen reader, high contrast, and accessibility hooks.

3.4 `crates/animus-compositor`
    - Purpose: Production Wayland compositor binary and shell surface orchestrator.
    - Key Files:
      * `src/main.rs`: Compositor entry point with 4 Calloop event sources (144Hz timer,
        Wayland socket, udev device hotplug, libinput seat).
      * `src/session.rs`: `vitusos-session` runner initializing HEV, StateManager, and EventBus.
      * `src/shell_controller.rs`: Central event dispatch routing input events to active surfaces.
      * `src/compositor_renderer.rs`: 7-layer scanout compositor combining Vulkan and Smithay.
      * `src/window_manager.rs` & `src/window.rs`: XDG shell toplevel management, stacking, tiling.
      * `src/workspace.rs`: Multi-workspace isolation and animated spatial transitions.
      * `src/shell/`: Complete set of macOS-grade desktop components:
        - `global_menu.rs`: AEMenuRegistered Top Panel with active app title and application menus.
        - `dock.rs`: Spring-magnified bottom dock with live app status indicators.
        - `cockpit_view.rs`: Mission Control / Expose workspace and window grid overview.
        - `control_center.rs`: Quick toggles for WiFi, Bluetooth, Audio, Display brightness.
        - `notifications.rs`: Interactive notification toast stack.
        - `lock_screen.rs`, `welcome_screen.rs`, `shutdown_screen.rs` ("Goodbye" screen).

3.5 `crates/animus-hev`
    - Purpose: Hardware Enclave & Vault for security, credentials, and cryptographic storage.
    - Key Files:
      * `src/hev.rs`: Master HEV controller interfacing with TPM 2.0 / secure storage.

3.6 `crates/animus-cache`

5.1 CompositorRenderer -- Production Frame Compositing
    This is the subsystem that actually places pixels on screen. Every frame, the
    compositor tick loop executes `CompositorRenderer::composite_frame(&shell)`:
    1. Extracts window geometry from the WindowManager's spring-animated positions
       into RenderWindow structs (position, size, shadow offset, corner radius,
       altitude, focus state).
    2. Extracts shell state -- dock item count, control center open, focused app title for Panel.
    3. Renders the 7-layer pipeline -- wallpaper, window shadows, glass backgrounds,
       window content, shell surfaces, boot crossfade, floating overlays.
    4. Renders CockpitView overlay -- darkens background via alpha blend, draws each
       card with shadow/glass/squircle at spring-animated positions and scale.
    5. Renders shell overlays -- LockScreen (#1A1208 full screen), WelcomeScreen
       (card with glass material), ShutdownScreen (full black), SystemScreen (blackout with alpha),
       Notification toasts (slide-in from top-right with glass).
    6. Produces a ScanoutFramebuffer ready for DRM/Winit scanout.

5.2 Production tick() Loop Wiring
    The compositor's tick() method is fully wired with end-to-end event flow:
    1. EventBus drain -- drain_async_queue() triggers all pending async event publishes.
    2. Event dispatch via crossbeam channel -- an EventBus subscriber sends every
       AEEvent through a crossbeam channel. The tick loop drains this channel and
       calls ShellController::dispatch_event() for each event. This routes every
       AEEvent (window open/close/focus, lock screen, cockpit view, fullscreen, volume,
       notifications, reduced motion, etc.) through the ShellController to the correct component.
    3. Shell update -- ShellController::update(dt) updates all shell springs (Panel,
       Dock, CockpitView, LockScreen, WelcomeScreen, ControlCenter, NotificationCenter,
       ShutdownScreen, SystemScreen, WindowManager).
    4. Window sync -- WindowManager windows are synchronized to the legacy Vec<AEWindow>
       for backward compatibility.
    5. Frame compositing -- CompositorRenderer::composite_frame(&shell) reads the entire
       shell state and writes the composited frame to the ScanoutFramebuffer.

    Canonical Event Flow:
    InputRouter -> EventBus -> crossbeam channel -> ShellController.dispatch_event()
      -> ShellController.update(dt) -> CompositorRenderer.composite_frame()
      -> ScanoutFramebuffer -> DRM/Winit scanout

6. BRUTAL REALITY CHECK: THE 1% MILESTONE
--------------------------------------------------------------------------------
While having 10 compiling Rust crates, 25,525 LOC, and 238 passing unit tests
proves that the internal mathematical foundations, state machines, and software
compositing pipelines are sound in memory, this represents approximately 1%
of a complete, fully functional, bootable, production operating system.

Major Critical Chasms Remaining:
1. Bare-Metal KMS/DRM Pageflipping:
   The software rasterizer outputs to a `Vec<u32>` buffer in RAM. Real scanout requires
   Vulkan WSI / DRM-KMS CRTC modesetting and hardware scanout plane pageflipping at 144Hz.
2. Real Wayland Client Surface Commit (wl_buffer / dmabuf):
   Passing client-rendered textures (Firefox, Chromium, Alacritty, MPV) into the
   CompositorRenderer pipeline via Linux DMA-BUF and wl_shm imports.
3. Hardware Libinput Seat:
   Translating raw `/dev/input/event*` evdev packets into gesture streams on real trackpads.
4. Real PipeWire Audio Server:
   Routing decoded PCM streams through real PipeWire node graphs rather than mock sinks.
5. Live Distro ISO & Bootable Media:
   Packaging the Linux kernel, initramfs, AnimusBoot.efi, systemd targets, and rootfs
   into a bootable UEFI ISO image that installs and boots on physical bare metal.
